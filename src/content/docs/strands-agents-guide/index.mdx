Strands Agents is an open-source (Apache 2.0) SDK from AWS for building agents. It is **model-driven**: you give an agent a model, a system prompt and tools, and the model plans the steps and decides when it is done. The SDK supplies the loop around that: tool execution, conversation management, sessions, hooks and policies, multi-agent orchestration, MCP and A2A, and OpenTelemetry tracing. It uses Amazon Bedrock by default and works with Anthropic, OpenAI, Google and other providers.

## The idea in one example

```python
from strands import Agent, tool


@tool
def get_weather(city: str) -> str:
    """Get today's forecast for a city.

    Args:
        city: City name.
    """
    return f"Light rain in {city}, 14°C"


agent = Agent(model="us.anthropic.%%model=anthropic%%", tools=[get_weather])
agent("Do I need an umbrella in Leeds today?")
```

There is no graph to draw and no prompt template to fill: the model sees the tool's schema, decides to call it, reads the result and answers. Everything else in the SDK is about controlling that loop: bounding it, observing it, persisting it, pausing it for a human, and combining several agents.

## Python or TypeScript

| | Python | TypeScript |
|---|--------|------------|
| Package | `strands-agents` (+ `strands-agents-tools`, `strands-agents-evals`) | `@strands-agents/sdk` |
| Runtime | Python 3.10+ | Node.js 22+, ESM only |
| Tools | `@tool` functions (schema from type hints and docstrings) | `tool()` with Zod schemas, fully typed |
| Providers | Bedrock, Anthropic, OpenAI, Gemini, LiteLLM, Ollama, Mistral, llama.cpp, Llama API, SageMaker, Writer | Bedrock, Anthropic, OpenAI, Google, Vercel AI SDK |
| Multi-agent | Agents as tools, `Swarm`, `GraphBuilder`, `workflow` tool, A2A | Agents as tools, `Swarm`, `Graph`, A2A |
| Extras | Evals package, real-time voice (`BidiAgent`), the larger tool library | Vended tools only |

Both SDKs share the concepts and most names, so moving between them is mostly syntax. Choose by the language of the service the agent lives in; choose Python if you need evals, the wider tool set or a provider only Python supports.

## When to choose Strands

**Good fit:**

- Tool-using agents where the model should plan the steps, rather than a fixed workflow you would draw as a graph.
- Agents on AWS: Bedrock models, IAM credentials, AgentCore Runtime hosting, AgentCore Memory and Gateway all fit without glue.
- Teams that want one SDK across providers, with the option of Python or TypeScript.
- Multi-agent systems that start simple (a supervisor with specialists as tools) and grow into swarms or graphs.

**Consider something else when:**

- You need explicit, checkpointed state machines with time travel and branching as the core design: [LangGraph](/langgraph-guide/) is built around that.
- You are committed to OpenAI's platform features (hosted tools, Realtime, tracing dashboard): the [OpenAI Agents SDK](/openai-agents-sdk-guides/) fits more naturally.
- You want a fully managed agent with no code at all: AgentCore's managed harness or Bedrock Agents (see the [Amazon Bedrock guide](/amazon-bedrock-agents-guide/)).

## Strands, Bedrock and AgentCore

These are three different things that work well together:

| Piece | What it is | Where it is covered |
|-------|-----------|---------------------|
| **Strands Agents** | An SDK: the agent loop runs in your process | This guide |
| **Amazon Bedrock** | The model service; Strands' default provider (`BedrockModel`), plus Guardrails and Knowledge Bases | [Model providers](/strands-agents-guide/python/strands_comprehensive_guide/#amazon-bedrock) |
| **Amazon Bedrock AgentCore** | Managed infrastructure for agents written with any framework: Runtime (hosting), Memory, Gateway (tools as MCP), Identity, Code Interpreter, Browser, Observability | The [Amazon Bedrock guide](/amazon-bedrock-agents-guide/) |

A typical AWS deployment is a Strands agent inside a `BedrockAgentCoreApp` on AgentCore Runtime, calling Bedrock models, keeping conversations in AgentCore Memory and reaching internal APIs through AgentCore Gateway. Strands does not require AgentCore, or even AWS: the same agent runs in Lambda, a container, or on your laptop against the Anthropic or OpenAI API. Hosting is covered on the production pages ([Python](/strands-agents-guide/python/strands_production_guide/), [TypeScript](/strands-agents-guide/typescript/strands_typescript_production/)).
