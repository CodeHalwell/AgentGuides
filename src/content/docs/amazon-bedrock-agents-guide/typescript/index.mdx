**AWS-native agents in Node.js.** Write the agent with the **Strands Agents TypeScript SDK** (`@strands-agents/sdk`) and host it on **AgentCore Runtime** with the **AgentCore TypeScript SDK** (`bedrock-agentcore`). The split is the same as in Python: Strands is the agent loop, AgentCore is where it runs and the managed services around it.

## Minimal example

A Strands agent on Claude Sonnet 5.5, served with the AgentCore Runtime HTTP contract (`GET /ping`, `POST /invocations` on port 8080):

```typescript
import { BedrockAgentCoreApp } from 'bedrock-agentcore/runtime'
import { Agent, BedrockModel, tool } from '@strands-agents/sdk'
import { z } from 'zod'

const getWeather = tool({
  name: 'get_weather',
  description: 'Get the current weather for a city.',
  inputSchema: z.object({ city: z.string() }),
  callback: ({ city }) => `It is 18°C and cloudy in ${city}.`,
})

const agent = new Agent({
  model: new BedrockModel({ modelId: 'us.anthropic.claude-sonnet-5-5', region: 'us-west-2' }),
  systemPrompt: 'You are a concise assistant.',
  tools: [getWeather],
  printer: false,
})

const app = new BedrockAgentCoreApp({
  invocationHandler: {
    requestSchema: z.object({ prompt: z.string() }),
    process: async (request, context) => {
      const result = await agent.invoke(request.prompt)
      return { result: result.toString(), sessionId: context.sessionId }
    },
  },
})

app.run()
```

```bash
npx tsx main.ts &
curl -s -X POST http://localhost:8080/invocations \
  -H 'Content-Type: application/json' \
  -H 'X-Amzn-Bedrock-AgentCore-Runtime-Session-Id: local-session-0000000000000000000001' \
  -d '{"prompt": "What is the weather in Leeds?"}'
```

Deploy it with the AgentCore CLI (`agentcore create --language TypeScript --framework Strands`, then `agentcore deploy`); see the [production page](/amazon-bedrock-agents-guide/typescript/agentcore_typescript_production/).

## Key concepts

- **Agent** (`@strands-agents/sdk`): model + system prompt + tools; `invoke()` returns an `AgentResult`, `stream()` yields typed events.
- **Tools**: `tool()` with a Zod schema gives typed, validated inputs. Agents, MCP clients and vended tools all go in the same `tools` array.
- **BedrockModel**: Bedrock Converse API with any Bedrock model or inference profile, such as `us.anthropic.claude-sonnet-5-5`; guardrails and prompt caching are options on the model.
- **BedrockAgentCoreApp** (`bedrock-agentcore/runtime`): the Runtime server; a Zod `requestSchema` types the payload, and an async generator handler streams Server-Sent Events.
- **AgentCore Memory**: plugged into Strands as a `MemoryStore` via `createAgentCoreMemoryStores()`.
- **Code Interpreter and Browser**: managed sandboxes exposed as Strands tools (`CodeInterpreterTools`, `BrowserTools`) or used through their clients.
- **Identity**: `withApiKey` and `withAccessToken` fetch outbound credentials from AgentCore Identity inside a handler.

## Coverage compared with the Python guides

| Topic | TypeScript | Notes |
|-------|-----------|-------|
| Strands agents, tools, streaming, hooks | Yes | Same concepts; `invoke()` instead of calling the agent |
| Strands multi-agent | `Graph`, `Swarm`, agents as tools | No `Workflow` pattern |
| AgentCore Runtime app | Yes | `invocationHandler.process` instead of `@app.entrypoint` |
| AgentCore Memory | Strands `MemoryStore` only | No `MemoryClient`; use `@aws-sdk/client-bedrock-agentcore` for raw calls |
| Code Interpreter, Browser | Yes | Strands tool wrappers are experimental |
| Identity | Yes | Wrapper functions instead of decorators |
| Gateway | No SDK module | Use Gateway as an MCP server via Strands `McpClient` |
| Observability | No SDK module | Strands OpenTelemetry via `@strands-agents/sdk/telemetry` |
| Bedrock Agents (Classic) | Not covered | Use `@aws-sdk/client-bedrock-agent-runtime` directly; the service is in maintenance mode |
