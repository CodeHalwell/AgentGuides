**Event-driven agentic workflows for TypeScript.** `@llamaindex/workflow` models agents as typed events and handlers, with RAG primitives available from the `llamaindex` umbrella package.

<Aside type="danger" title="Deprecated upstream">
  LlamaIndex.TS is **no longer maintained**. The [LlamaIndexTS repository](https://github.com/run-llama/LlamaIndexTS) carries a deprecation notice, and npm marks `@llamaindex/workflow`, `@llamaindex/workflow-core`, `@llamaindex/core` and the provider packages as deprecated (`@llamaindex/workflow-core` points to LlamaAgents / Python Workflows instead). The final releases still install and the guides below document them accurately, but there will be no further fixes. For new TypeScript projects prefer a maintained framework such as [LangGraph.js](/langgraph-guide/typescript/) or the [OpenAI Agents SDK](/openai-agents-sdk-typescript-guide/), or call [LlamaIndex (Python)](/llamaindex-guide/python/) behind an API.
</Aside>

## Notes on the final release

- `runWorkflow()`, `runAndCollect()` and `runStream()` are marked `@deprecated`; use `run(workflow, event).until(stopEvent).toArray()` instead.
- `handle()` mutates the workflow in place and returns `void` — method chaining is not supported.
- Handler signature is `(ctx, ...events)`: the first argument is the workflow context; subsequent arguments are the matched input events in order.
- Agent workflows built with `agent(...)` / `multiAgent(...)` expose `run()` (a Promise of the final stop event) and `runStream()` (all events).

## Install, minimal example

`@llamaindex/workflow` uses a **functional API** — `createWorkflow`, `workflowEvent`, `run`. A class-based `extends Workflow` + `@step()` pattern is the *Python* API and does not exist in the TypeScript package.

```typescript
import { createWorkflow, workflowEvent, run } from '@llamaindex/workflow';

// Define typed events — the generic parameter is the payload type
const startEvent = workflowEvent<{ input: string }>({ debugLabel: 'start' });
const stopEvent  = workflowEvent<{ result: string }>({ debugLabel: 'stop' });

// Build the workflow — handle() mutates in place; it does not return the workflow
const workflow = createWorkflow();
workflow.handle([startEvent], async (ctx, start) => {
  return stopEvent.with({ result: `Echo: ${start.data.input}` });
});

const events = await run(workflow, startEvent.with({ input: 'Hello!' }))
  .until(stopEvent)
  .toArray();
console.log(events.at(-1)?.data); // { result: 'Echo: Hello!' }
```

For runtime validation of payloads, `zodEvent(schema)` creates an event type from a Zod schema.

For multi-agent topologies use `multiAgent(...)` + `FunctionAgent`. For streaming use `run(...).toStream()` or iterate the return value of `run(...)` directly.
