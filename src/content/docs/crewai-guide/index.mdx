## Behaviours that differ from what you might expect

These were found by tracing what agents and tasks actually receive, and each is covered where it applies.

- `Agent(guardrail=...)` only applies to `Agent.kickoff()`. In a crew, use `Task.guardrail` ([Agent API](/crewai-guide/crewai_agent_api_python/#guardrails)).
- `Task(response_model=...)` leaves `TaskOutput.pydantic` empty; use `output_pydantic` for a parsed result ([Task API](/crewai-guide/crewai_task_api_python/#structured-output-three-fields-one-answer)).
- Task outputs reach later tasks as context text, not as `{variables}` ([Task API](/crewai-guide/crewai_task_api_python/#context-and-task-chaining)).
- In a hierarchical crew the manager runs every task, and `{placeholders}` are not interpolated into a `manager_agent`'s own text ([Multi-agent patterns](/crewai-guide/crewai_advanced_multi_agent_python/#manager-led-crews)).
- Tool-result caching is opt-in at the crew or agent level ([Tools](/crewai-guide/crewai_tools_python/#caching)).
- `step_callback` sees tool steps only on the text (ReAct) path; with native function calling it fires once with the final answer ([Agent API](/crewai-guide/crewai_agent_api_python/#callbacks-and-observability)).
- String knowledge paths are always resolved under `knowledge/`, and each task with knowledge makes an extra LLM call ([Knowledge](/crewai-guide/crewai_knowledge_python/)).
- `Task(input_files=...)` needs `crewai[file-processing]` and `File(...)` objects ([Task API](/crewai-guide/crewai_task_api_python/#file-inputs)).
- `Memory.forget(scope=..., older_than=...)` deleted newer records in 1.15.28 ([Memory](/crewai-guide/crewai_memory_python/#forget-and-update)).
- `crewai train` asks you for feedback on every task ([CLI](/crewai-guide/crewai_cli_python/#training-mode)).

## What's new in the 1.15 line (June–October 2026)

- **JSON-first scaffolds** — `crewai create crew` now runs an interactive wizard and writes `crew.jsonc` + `agents/*.jsonc`. Pass `--classic` for the Python/YAML `@CrewBase` layout this guide uses. Tools, skills and templates are scaffolded through the same command (`crewai create tool|skill|template`); the older `crewai tool create` / `crewai template add` forms are deprecated.
- **Declarative and conversational flows** — `crewai create flow --declarative`, `crewai run --definition <file>`; conversational flows are stable since 1.15.18. `crewai run` runs flows as well as crews.
- **`crewai eval`** — grades the last traced run through CrewAI AMP and exits non-zero on a failed gate; `--models` compares models on a deployment.
- **Agent defaults** — the newer `AgentExecutor` is now the default `executor_class`; new `skills=` and `tool_failure_policy=` fields; tool failures are surfaced rather than reported as success.
- **Packaging** — the CLI moved to its own `crewai-cli` distribution (installed with `crewai`; `crewai.cli` is a deprecated alias for `crewai_cli`). Provider SDKs and LiteLLM are optional extras (`crewai[anthropic]`, `crewai[google-genai]`, `crewai[bedrock]`, `crewai[litellm]`).
- **New native providers** — Snowflake and DeepInfra join the native list; DashScope routes natively for all models.
- **Memory** — default analysis model `gpt-5.4-mini` and embedder `text-embedding-3-large`; stores built with the old 1536-dimension default need a reset or an explicit embedder (see [Memory](/crewai-guide/crewai_memory_python/)).

## Earlier highlights (1.14 line, April–May 2026)

- **Checkpoint system** (1.14.0, yanked; first usable release 1.14.1) and checkpoint forking with lineage tracking (1.14.2).
- **`from_checkpoint` on `Crew.kickoff` / `Flow.kickoff` / `Agent.kickoff`** — resume with `from_checkpoint=CheckpointConfig(restore_from=...)`.
- **Checkpoint CLI** — `crewai checkpoint list|info|resume|diff|prune`.
- **Enriched token tracking** — `reasoning_tokens`, `cache_creation_tokens` on `CrewOutput.token_usage`.
- **Scoped streaming handlers** — per-run isolation across concurrent crews.

<Aside type="caution" title="Breaking and behavioural changes since v1.5.0">
  - `CodeInterpreterTool` removed from the public API (1.14.0/1.14.1) — use E2B / Modal / a custom `BaseTool`.
  - `CrewStructuredTool` moved to internal API — external code should use `BaseTool`.
  - `stop=` parameter stripped for GPT-5 / o-series (and later OpenAI reasoning) models by the LLM router.
  - `Agent.reasoning` deprecated → use `planning` + `PlanningConfig`.
  - `function_calling_llm` (on `Agent` and `Crew`) marked deprecated in the 1.15 line.
  - `Agent.multimodal` deprecated → use `Task.input_files=...`.
  - `StateProxy` removed from flow state access (1.15.0).
  - `crewai create crew` defaults to the JSON-first layout (1.15 line) — add `--classic` for YAML.
  - LiteLLM is no longer installed by default; non-native model prefixes need `crewai[litellm]`.
  - `from crewai.amp import ...` **is not a valid import**. AMP is accessed through the CLI (`crewai login`, `crewai deploy ...`) and `Agent(apps=[...])`.
  - Yanked from PyPI: 1.10.0, 1.12.0 and **1.14.0** (broken Anthropic dependency). Use 1.10.1+, 1.12.1+ and 1.14.1+.
</Aside>

## Install, minimal example

```python
from crewai import Agent, Task, Crew, Process, LLM

llm = LLM(model="openai/%%model=openai-small%%")

analyst = Agent(
    role="Research Analyst",
    goal="Analyse topics thoroughly",
    backstory="Expert analyst with 10 years of experience",
    llm=llm,
)

task = Task(
    description="Research AI advancements in 2026",
    expected_output="Concise analysis of key developments",
    agent=analyst,
)

crew = Crew(agents=[analyst], tasks=[task], process=Process.sequential)
result = crew.kickoff()
print(result)
```
